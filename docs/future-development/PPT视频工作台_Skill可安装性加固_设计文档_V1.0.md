# PPT 视频工作台 Skill 可安装性加固设计文档 V1.0

## 1. 目标

将仓库内的 `ppt-video-workbench` Codex Skill 加固为可从公开仓库稳定安装、在安装副本中可定位自身脚本、按实际工作能力输出可信预检结果，并以可执行行为测试证明这些契约。目标版本为 v0.1.2；本轮不创建标签、Release 或插件。

### 包含

- 修复 README 的安装入口，使其明确传递仓库、分支引用和 Skill 路径。
- 定义 `source`、`office-import`、`render` 三种预检能力，并让 READY 仅代表所选能力已满足。
- 让 SKILL.md 使用 `<skill-dir>` 指向安装后的脚本，而不假设仓库当前目录。
- 为预检模式和安装副本运行路径加入自动化行为测试。

### 不包含

- 不将 Skill 打包为 Codex 插件、不新增 `.codex-plugin`。
- 不改动视频工作台应用、渲染引擎、模型、真实数据或正式发布流程。
- 不合并主分支、不打 v0.1.2 标签、不创建 GitHub Release。

## 2. 范围

代码范围限于 `skills/ppt-video-workbench/`、`tests/skills/`、仓库 README 与本计划文档。分支固定为 `codex/skill-v012-installability`，来源提交为公开默认分支的 `72cb7bbee6fb2fa21485f77d627a8f1443d61eb8`。

## 3. 现状与约束

- 现有 README 使用含斜杠分支名的 `/tree/<ref>/<path>` URL；安装器会将 `codex` 误识别为 ref，因而不能稳定解析。
- 现有预检将 `ffmpeg`、`ffprobe`、`soffice` 标为非阻断缺失，却仍可能报告 READY，与渲染和 Office 导入实际需要相矛盾。
- SKILL.md 硬编码仓库内相对路径；安装后并非总有同名仓库根目录。
- 所有改动必须局限于隔离 X 盘 worktree；现有主集成 worktree 有用户脏改动，不能触碰。
- 当前公开 Release `v0.1.1` 不含此 Skill，不能声称当前已发布的 Release 可安装它。

## 4. 模块与依赖关系

| 模块ID | 模块 | 被谁依赖 | 依赖满足标准 |
| --- | --- | --- | --- |
| M01 | 安装说明 | M04 | 安装提示同时给出 owner/repo、ref、path，且不使用歧义 URL |
| M02 | 能力预检 | M03、M04 | source/render/office-import 均有明确必需工具和 READY 判定 |
| M03 | Skill 自定位 | M04 | 所有预检命令从 `<skill-dir>/scripts/preflight.py` 执行 |
| M04 | 行为测试 | 完成门禁 | 测试覆盖能力缺失、外部 repo 和安装副本执行 |

## 5. 方案选择

### 方案 A：独立 Skill 加固（推荐）

保留现有独立 Skill 布局；README 采用安装器可理解的 `repo + ref + path` 指令；预检按能力建模；Skill 使用安装目录变量；以 Python 自动化测试验证。

### 方案 B：立即迁移为 Codex 插件

同时创建插件清单、安装入口与分发结构，依靠插件承载 Skill。

### 最终推荐

采用方案 A。

### 推荐理由

它精确修复当前公开仓库的安装与可信 READY 问题，不改变应用运行机制，也不引入插件生命周期、清单兼容性和发布流程的额外变量。插件化作为 v0.2.0 候选项保留，待本 Skill 已有稳定安装与行为证据后再评估。

### 自动采用边界

允许自动修改 Skill、测试、README、项目规划文档并运行本地验证。禁止自动合并、打标签、创建 Release、上传任何包、修改公开仓库设置或使用真实个人数据；这些动作须由维护者最终决定。

## 6. 整体完成标准

- [ ] README 不再使用含斜杠 ref 的歧义 `/tree/<ref>/<path>` 安装 URL。
- [ ] 预检的 JSON 输出包含 capability、blocking 工具和 READY，且渲染/Office 缺工具时返回非零。
- [ ] SKILL.md 的预检命令可由安装目录变量执行，且不会把 Skill 目录误作应用仓库。
- [ ] Skill 测试在隔离 worktree 中全绿，计划门禁和 X 盘合规检查均通过。
- [ ] 形成可审查提交；正式版本、Release 与插件均未发布。

## 7. 验证策略

先以失败测试锁定预检能力契约，再实现最小代码；随后运行单元/行为测试、Skill 验证器、README/引用交叉检查、X 盘合规检查和计划门禁。将命令、退出码、关键输出、Git 状态保存至专属 X 盘证据目录。自动测试只证明工程契约；维护者仍需决定是否合并和发布。

## 8. 风险与回滚

| 风险 | 缓解 | 回滚 |
| --- | --- | --- |
| 严格预检阻断旧的仅源码操作 | `source` 保持最小工具集，额外能力按需显式选择 | 回退本分支上的预检与说明提交 |
| 说明与安装器语义再次漂移 | 行为测试覆盖安装副本脚本，发布前人工复制安装指令验证 | 回退 README/SKILL.md 提交 |
| 插件需求被误解为已完成 | 文档明确标为下一阶段且不新增插件文件 | 保持当前独立 Skill 布局 |
