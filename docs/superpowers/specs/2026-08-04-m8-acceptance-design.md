# M8 实机验收设计规格

## 范围与不可替代的实机证据

M8 覆盖 Task 37—40：验收数据集与需求追踪、自动化端到端/非功能测试、真实 6—8 页项目验收、RC 修复与 V1.0 冻结。

当前容器可以执行 Python、Web、Remotion、API、Playwright、契约、安全和恢复测试，但不能替代 Windows 10/11 干净 VM、真实 PowerPoint/Office、真实用户声音、真实 HeyGen 小额请求或人工视听。因此：

- 自动化报告可以作为 RC 候选证据；
- Windows 实机报告必须明确 `pending_manual_windows`，未完成前不签署 V1.0；
- 真实接口只允许在用户提供受控凭证和明确实机环境后执行，当前不发起真实付费请求；
- 任何 P0/P1、哈希不一致、数据损坏或人工视听未验收都阻止 release tag。

## 追踪矩阵

Task 37 建立 `FR-001`—`FR-016` 与 `NFR-001`—`NFR-007` 的逐行矩阵。每行必须包含需求描述、优先级、验收测试 ID、前置条件、步骤、期望、证据路径、执行环境和结果。矩阵同时导出为 `docs/traceability.xlsx` 和 JSON 可审查源。

FR-016 固定为多图片输入的自然排序与人工调整，来源是正式计划中对图片输入场景的补充约束。

## 自动化回归

Task 38 增加：

- 本地音频全链路入口与现有 M4/M5 集成测试的证据映射；
- fake HeyGen、单页失败、重试和无付费请求约束；
- 8 页性能/磁盘/中文路径/恢复/安全检查清单；
- Playwright 核心工作台 smoke，真实 Windows-only 场景以明确 skip/待执行标记隔离。

自动化测试不把缺少真实素材时的空壳响应称为完整制作成功；每个未执行项必须写入报告原因和实机命令。

## 真实项目验收

Task 39 提供 RC1 结果目录、截图/产物清单和报告模板，覆盖真实 Word+PPTX、Word+扫描 PDF、Word+多图片、本地录音、2 页真实声音、暂停/关闭/恢复、单页旁白修改和人工视听。模板默认 `P0=未评估、P1=未评估、签署=未签署`。

## V1.0 冻结

Task 40 提供变更日志、release notes、签署文件和冻结检查。只有以下条件全部满足才允许 `v1.0.0`：

1. 追踪矩阵无空缺、无孤立测试；
2. 自动化 Gate 全绿；
3. Windows 安装/更新/回滚和真实 6—8 页报告签署；
4. P0/P1 为零，P2 有明确处置；
5. 安装器、哈希、SBOM、许可证、手册、演示项目和完整制作包已归档。

在当前环境中只建立可审查候选发布物，不创建 V1.0 tag。
