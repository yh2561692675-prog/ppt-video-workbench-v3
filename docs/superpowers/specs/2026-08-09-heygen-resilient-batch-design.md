# HeyGen 整批页面配音容错设计

## 背景与根因

r21 已支持把单页长旁白拆成多个分段并保存分段完成状态，但仍存在两层中断点：

1. 单个 HeyGen 分段只有两次同步请求机会，连续两次超时后整页返回失败。
2. Web 端按页串行调用单页接口，任一页面失败便退出整个循环，用户只能再次点击，把失败逐页向后推进。

现有八页回归仅覆盖“某页第一次失败、第二次成功”，没有覆盖同一分段连续超时，也没有覆盖页面失败后继续处理后续页面。

## 目标

- 一次点击尽可能自动完成所有页面，不因单个可恢复故障中断整批。
- 已成功页面和已成功分段必须复用，不重新合成。
- 可恢复故障最多进行三轮页面级补跑；每个远端分段最多进行三次有限退避请求。
- 只有认证失败、额度不足、音频路线冲突、明确要求更换声音等确定性错误立即停止。
- 达到有限上限后只显示一次失败页面汇总，不逐页弹错或无限重试。
- 不修改项目旁白、已完成音频、声音选择、语速或本地录音互斥规则。

## 方案

### 后端分段与请求容错

- 默认旁白分段上限由 120 个字符降为 60 个字符，仍优先在中文句号、问号、叹号、分号和逗号处切分。
- `HeyGenClient.generate_speech` 对 `timeout`、网络错误和服务端暂时错误最多请求三次。
- 两次重试之间采用 2 秒、4 秒退避，重试次数和等待函数可注入，保证测试不真实等待。
- 每一分段成功后立即写入现有分段状态文件；后续页面级补跑只请求缺失分段。

### Web 整批调度

- 第一轮按原页面顺序处理全部页面。
- 可恢复错误只把页面放入下一轮队列，不中断本轮；因此第 5 页超时后仍会继续第 6—8 页。
- 后续轮次只处理失败页面，最多三轮。
- 成功页面以页面 ID 去重计数；同一页面补跑成功不会重复增加进度。
- `ApiRequestError` 保留服务端错误码、动作和 HTTP 状态，界面据此区分可恢复与不可恢复错误。
- 三轮后仍失败时显示一次汇总，包括失败页码和最后错误；用户再次点击仍可依赖后端分段缓存续跑。

## 错误分类

可自动补跑：`heygen_timeout`、`heygen_network_error`、`heygen_service_error`、`heygen_rate_limited`、`heygen_empty_audio`，以及浏览器层临时网络异常。

立即停止：`heygen_authentication_failed`、`heygen_quota_exhausted`、`audio_route_switch_required`、`heygen_regeneration_confirmation_required`，以及其他未明确列入可恢复集合的 API 契约错误。

## 验收

1. 三页模拟中，第 2 页前两轮失败时，第 3 页仍在第一轮被处理；第 2 页第三轮成功后整批显示完成。
2. 同一分段前两次超时、第三次成功时，单页接口成功，并记录两次退避。
3. 连续三次超时后请求停止，不出现无限循环。
4. 已完成的前四页通过缓存返回，不重新请求 HeyGen。
5. 三轮后仍有多个失败页时只显示一条汇总。
6. 现有 Python、Web、类型、格式和契约回归保持通过。
